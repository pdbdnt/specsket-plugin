# Hosts that can compute canonical digests

Part of [the rules for specific situations](ingestion-conditional-rules.md).

Plugin-only agents skip this file (the skill's strict sequence, step 4). A host that can compute canonical digests may calculate the digest of the exact `product_presentation.product_structure`, include it as `product_structure.product_structure_digest` in the complete compact immutable descriptor, and, when it is listed, call the read-only planner (`specsket_plan_product_ingestion_jobs`; it is offered to platform administrators on the operator address, not to vendors or designers). Include its complete limit preflight in the preview: parent record IDs and counts, combinations per parent, immutable job structure and unresolved-node count, deterministic partition proposal, repeated structure-evidence/body cost, logical media roles, exact URL-digest duplicate count, expected record-local fetches, workload warnings, and separate `fits_record`, `fits_job`, and `fits_chunk` results. Job manifests contain parent product IDs only. The planner returns both `partition_digest` (the compact partition plan) and `structure_digest` (the exact Product Wizard topology); pass `structure_digest`, never `partition_digest`, in `media_preflight_binding`. Treat `fits_record`, `fits_job`, and `fits_chunk` as independent outcomes; validation chunks are not topology partitions. If the job-wide unresolved structure exceeds its limit, accept only deterministic parent-boundary partitions, never split one parent, rebuild an independently valid structure/checkpoint for each proposed job, recalculate its canonical structure digest, and rerun the planner before validation. URL digests are equality counters only: preserve submitted URLs byte-for-byte and never treat a URL digest as a fetchable URL or a pre-fetch content hash. Request validation advisory metadata for the exact unchanged chunk and report `fits_job: unknown` whenever the complete repeated topology binding is absent.
